Memory management decides **where** each process lives in physical memory, keeps processes from touching each other's memory, and makes efficient use of limited RAM.

## Logical vs physical addresses

| | Logical (virtual) address | Physical address |
|---|---|---|
| Generated by | the CPU / program | seen by the memory unit |
| Range | 0 … max of the process's address space | actual RAM locations |
| Translation | by the **MMU** (Memory Management Unit) at run time | — |

```diagram Dynamic relocation with base (relocation) and limit registers
 CPU ── logical 346 ──► [ 346 < limit 1000 ? ] ── yes ──► [ + base 14000 ] ──► physical 14346
                               │ no

                        trap: addressing error
```

## Address binding

| When | Result |
|---|---|
| Compile time | absolute code; must load at a fixed location |
| Load time | relocatable code; addresses fixed when loaded |
| **Execution time** | addresses translated on every access by the MMU — allows moving processes in memory (used by modern OSes) |

## Loading and linking

- **Static linking**: library code copied into the executable.
- **Dynamic linking**: libraries (`.so`, `.dll`) linked at load/run time and shared between processes.
- **Dynamic loading**: a routine is loaded only when first called.

## Swapping

A process can be temporarily moved from memory to a **backing store** (disk) and brought back later. It lets the total memory of all processes exceed RAM, at the cost of slow disk I/O. Modern systems swap **pages**, not whole processes.

## Contiguous memory allocation

Each process occupies one contiguous block.

### Fixed partitioning

Memory is divided into fixed-size partitions. Simple, but causes **internal fragmentation** (a small process wastes the rest of its partition) and limits the degree of multiprogramming.

### Variable (dynamic) partitioning

Partitions are created exactly as large as needed. Free blocks (**holes**) appear as processes exit → **external fragmentation**.

#### Placement strategies

| Strategy | Picks | Notes |
|---|---|---|
| **First fit** | the first hole big enough | fast; generally good |
| **Next fit** | first fit, starting from the last allocation | spreads allocations |
| **Best fit** | the smallest hole big enough | leaves tiny unusable holes; must search all |
| **Worst fit** | the largest hole | leaves big leftover holes; usually worst |

**Example**: holes of 100, 500, 200, 300, 600 KB; requests 212, 417, 112, 426 KB.

| Request | First fit | Best fit | Worst fit |
|---|---|---|---|
| 212 | 500 → 288 left | 300 → 88 left | 600 → 388 left |
| 417 | 600 → 183 left | 500 → 83 left | 500 → 83 left |
| 112 | 288 → 176 left | 200 → 88 left | 388 → 276 left |
| 426 | **must wait** | 600 → 174 left | **must wait** |

Here best fit is the only one that places all four requests.

```python
def allocate(holes, requests, strategy):
    holes = holes[:]
    placed = []
    for r in requests:
        fits = [i for i, h in enumerate(holes) if h >= r]
        if not fits:
            placed.append(None)
            continue
        if strategy == "first":
            i = fits[0]
        elif strategy == "best":
            i = min(fits, key=lambda k: holes[k])
        else:  # worst
            i = max(fits, key=lambda k: holes[k])
        placed.append(holes[i])
        holes[i] -= r
    return placed

for s in ("first", "best", "worst"):
    print(s, allocate([100, 500, 200, 300, 600], [212, 417, 112, 426], s))
```

```output
first [500, 600, 288, None]
best [300, 500, 200, 600]
worst [600, 500, 388, None]
```

## Fragmentation

| | Internal fragmentation | External fragmentation |
|---|---|---|
| What | wasted space **inside** an allocated block | enough total free memory, but not **contiguous** |
| Caused by | fixed-size blocks/partitions/pages | variable-size allocation |
| Fix | smaller block sizes | **compaction** (move processes together), paging, segmentation with paging |

> [!NOTE]
> Paging eliminates external fragmentation (any free frame works) but has internal fragmentation — on average half a page per process.

## Non-contiguous allocation

Instead of one block, a process is split into pieces placed anywhere:

- **Paging** — fixed-size pages mapped to frames (see *Paging*).
- **Segmentation** — variable-size logical segments (code, stack, heap) (see *Segmentation*).
- **Segmented paging** — segments divided into pages (x86 historically, many textbooks).

## Memory protection

- Base/limit registers (contiguous allocation).
- Valid–invalid bits and protection bits (read/write/execute) in page-table entries.
- Kernel memory marked supervisor-only.

> [!INTERVIEW]
> - *Logical vs physical address?* — CPU-generated vs actual RAM location, translated by the MMU.
> - *Internal vs external fragmentation?* — Waste inside a block vs scattered free holes.
> - *First vs best vs worst fit?* — First is fastest; best minimises leftover per allocation; worst usually performs worst.
> - *How does paging solve external fragmentation?* — Any free frame can hold any page, so memory need not be contiguous.

> [!REMEMBER]
> MMU translates logical → physical at run time. Contiguous allocation suffers external fragmentation (fix: compaction or paging). Fixed blocks suffer internal fragmentation. First fit is a solid default.
